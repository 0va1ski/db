# 🚀 C++ ЛАБОРАТОРНЫЕ РАБОТЫ

В этом репозитории собраны лабораторные работы по программированию на C++.
К каждой работе приложены теоретический минимум, варианты решения и инструкция по работе с кодом.

| Работа | Тема |
|---|---|
| [Лабораторная 5](laba5/README.md) | Массивы: векторы и матрицы |

> **Важно:** работайте в **своей копии** репозитория (форке), а не в оригинале.
> В оригинал отправлять изменения нельзя, а в своей копии вы можете сохранять решения и историю работы.
> Как её создать, описано ниже.

## 🌐 Онлайн-вариант

Если ставить компилятор не хочется, откройте любой `.cpp` файл, скопируйте код в
[онлайн-компилятор](https://www.onlinegdb.com/online_c++_compiler) и нажмите **Run**.

## 📦 Как начать работать

### Что понадобится

- Любая IDE для C++: [VS Code](https://code.visualstudio.com/), [CLion](https://www.jetbrains.com/clion/), [Dev-C++](https://www.embarcadero.com/free-tools/dev-cpp).
- Компилятор **g++**. На Windows проще всего поставить через [MSYS2](https://www.msys2.org/) и добавить папку `C:\msys64\ucrt64\bin` в переменную `Path`.
- [Git](https://git-scm.com/).
- Аккаунт на [GitHub](https://github.com/).

### Шаг 1. Проверьте, что всё установлено

Откройте терминал и выполните:

```bash
git --version
g++ --version
```

Если обе команды показали версию, можно продолжать.

### Шаг 2. Создайте свою копию репозитория (форк)

1. Откройте страницу оригинального репозитория: <https://github.com/0va1ski/isit>.
2. Нажмите кнопку **Fork** в правом верхнем углу.
3. Нажмите **Create fork**.

У вас появится копия репозитория по адресу `https://github.com/ВАШ_ЛОГИН/isit`.
Все дальнейшие действия выполняйте с ней.

> Форк публичного репозитория тоже публичный. Если нужна закрытая копия, нажмите
> **Use this template** (если эта кнопка есть на странице репозитория) и в настройках нового
> репозитория выберите **Private**.

### Шаг 3. Скачайте свою копию на компьютер

Подставьте **свой** логин вместо `ВАШ_ЛОГИН`:

```bash
git clone https://github.com/ВАШ_ЛОГИН/isit.git
cd isit
```

Первая команда скачивает репозиторий в папку `isit`, вторая переходит в неё.

### Шаг 4. Один раз представьтесь Git

Без этого первый коммит не получится. Укажите своё имя и почту, с которой вы зарегистрированы на GitHub:

```bash
git config --global user.name "Ваше Имя"
git config --global user.email "you@example.com"
```

### Шаг 5. Соберите и запустите программу

Готовых `.exe` в репозитории нет, программы нужно **собрать** самостоятельно. Формат команды:

```bash
g++ -std=c++17 исходный_файл.cpp -o имя_программы
```

Если сборка прошла успешно, команда ничего не выведет, а рядом появится готовый файл
(`имя_программы.exe` на Windows, `имя_программы` на Linux и macOS).
Если появились сообщения об ошибках, программа не собралась.

Запуск на Windows (PowerShell):

```powershell
.\имя_программы
```

Запуск на Linux и macOS:

```bash
./имя_программы
```

Конкретные команды для каждой работы смотрите в её собственном README.

### Шаг 6. Сохраняйте свои решения

Свои решения кладите в отдельную папку работы, например `laba5/my/`, и **не правьте файлы README**.
Так при обновлении из оригинала не возникнет конфликтов.

```bash
git add .
git commit -m "Решил задание a"
git push
```

- `git add .` подготавливает все изменения к сохранению.
- `git commit` сохраняет их в истории с вашим комментарием.
- `git push` отправляет их в ваш репозиторий на GitHub.

При первой отправке откроется окно входа в GitHub. Пароль от аккаунта GitHub для этого не подходит,
войдите через браузер в открывшемся окне.

### Шаг 7. Получайте новые лабораторные из оригинала

Один раз подключите оригинальный репозиторий как `upstream`:

```bash
git remote add upstream https://github.com/0va1ski/isit.git
```

Когда в оригинале появятся новые работы или исправления, забирайте их так:

```bash
git pull upstream main
git push
```

Первая команда скачивает обновления из оригинала в вашу копию, вторая отправляет их в ваш репозиторий на GitHub.

> Команду `git pull` без `upstream main` используйте только для обновления с вашего форка
> (например, если вы работаете на двух компьютерах).

## 🛠 Если что-то не работает

| Проблема | Что делать |
|---|---|
| `g++` не распознана | Компилятор не установлен или не добавлен в `Path`. После установки перезапустите терминал |
| `No such file or directory` | Вы не в той папке. Проверьте содержимое командой `dir` (Windows) или `ls` (Linux) |
| Запускается старая версия | После каждой правки кода программу нужно собрать заново |
| Ошибка при компиляции | Прочитайте первую строку с `error`, в ней указана строка кода с проблемой |
| Кракозябры вместо русского текста | Перед запуском выполните `chcp 65001` |
| `Updates were rejected` при `git push` | В вашем репозитории есть изменения, которых нет на компьютере. Выполните `git pull`, затем снова `git push` |
| Конфликт при слиянии | Не правьте файлы README, свои решения храните в своей папке. Если конфликт уже случился, выполните `git merge --abort` и обратитесь за помощью |
| `Permission denied` при `git push` | Вы клонировали оригинал, а не свой форк. Проверьте адрес командой `git remote -v` и склонируйте заново свой репозиторий |
